# Screens are written in Preact with htm, without a build step

Screens (Home, Detail, Live TV, Player overlays, Settings, Profiles) are rewritten as Preact components with htm templates as each one is redesigned under #31; logic modules (player engine, Xtream/M3U adapters, Progress, Prefs, storage, TMDB and OpenSubtitles clients) stay plain JavaScript globals. The owner chose Preact (about 4 KB) over vanilla DOM code because a screen becomes a template of what it shows, roughly half the code, re-renders itself when its state changes (several bugs this year were missed manual re-renders), and is a pattern people and agents already know, so changes cost less reading. React was rejected as about ten times larger with more memory and update work on a TV CPU; Angular (#18) remains a separate long-term port. htm parses templates in the browser, so the app still ships as plain files with no build step, and `preact` and `htm` are fetched into `tv-app/vendor/` like hls.js and mpegts.js (pinned versions, not committed).

The first Preact screen (Detail, ticket J) is measured on the TV against today's page (start-up, memory, key-press smoothness); a clear regression reopens this decision. Until a screen is migrated, vanilla and Preact screens live side by side, and the Playwright specs, which drive the remote and read the DOM, stay the contract for both.
